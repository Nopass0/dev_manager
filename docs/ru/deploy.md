# Деплой по SSH

> Раздел: [Документация](./README.md)

Dev Manager умеет выполнять последовательность shell-команд на удалённом хосте
по SSH. В текущей версии это каркас (трейт `Deployer` + заглушка); полноценная
реализация на `russh` подключается в следующей итерации.

## Конфигурация целей

```yaml
deploy:
  - name: prod
    host: prod.example.com
    user: deploy
    port: 22
    key: ~/.ssh/id_ed25519       # приватный ключ (~ раскрывается)
    remote_dir: /srv/my-app
    on: after_push               # когда запускать автоматически
    steps:                       # команды на удалённом хосте, по порядку
      - git pull
      - cargo build --release
      - systemctl restart my-app
```

## Триггеры (`on`)

| Значение | Когда срабатывает |
|---|---|
| `manual` | Только по явной команде `dm deploy <name>` (по умолчанию). |
| `after_commit` | После каждого успешного `dm commit`. |
| `after_push` | После каждого успешного `dm push`. |

## Запуск

```sh
dm deploy prod
```

`dm` подключается к хосту по ключу (или паролю), выполняет `steps` по порядку и
выводит результат каждой команды.

## Безопасность

- Ключи хранятся локально, в `~/.ssh/`; путь указывается в конфиге.
- Пароли в конфиге **не хранятся** — используйте SSH-агент или ключи.
- `remote_dir` — целевой каталог на сервере (для будущих операций rsync/scp).

## Текущий статус (v0.1)

В этой версии `dm deploy` выполняет **заглушку**: проходит по шагам и
выводит `[stub] шаг пропущен`. Это позволяет протестировать конфигурацию и
логику триггеров без реального подключения. Подключение `russh` (чистый Rust,
без C-зависимостей) — в roadmap.
