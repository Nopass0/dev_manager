# Multi-repo: коммит и пуш в несколько репозиториев

> Раздел: [Документация](./README.md)

Dev Manager поддерживает проекты, где микросервисы живут в **отдельных**
git-репозиториях. Укажите это полем `repo` в конфиге:

```yaml
services:
  api:
    path: ./services/api
    language: rust
    repo: ./services/api     # ← отдельный репозиторий
  web:
    path: ./services/web
    language: vite
    repo: ./services/web     # ← отдельный репозиторий
```

## Коммит во все репозитории

```sh
dm commit "feat: общее изменение"
```

`dm` выполнит `git add -A && git commit -m "feat: общее изменение"` в **каждом**
репозитории с одним и тем же сообщением. Отчёт:
```
✓ a1b2c3d ./services/api  — закоммичено
✓ e4f5g6h ./services/web  — закоммичено
```

## Коммит в конкретный репозиторий

```sh
dm commit api "fix: правка только в API"
```

`api` — имя сервиса из конфига. Закоммитится только соответствующий репозиторий.

## Пуш

```sh
dm push
```

Каждый репозиторий пушится в **свой** `origin` (согласно `git remote`). Это
позвляет держать сервисы в разных GitHub/GitLab-проектах.

## `dm commit auto`

Если не хотите писать сообщение вручную — используйте авто-режим:
```sh
dm commit auto
```

`dm` проанализирует изменённые файлы через tree-sitter, найдёт затронутые
функции/классы/структуры и сформирует читаемое сообщение:
```
auto: изменены 3 символ(ов)

- изменена функция parse (api/src/lib.rs)
- добавлена структура User (api/src/models.rs)
- удалена функция old_handler (web/src/handlers.ts)
```

Это сообщение коммитится во все репозитории (или в указанный).

## Смешанный монорепозиторий

Если часть сервисов в одном репо, а часть — в отдельных, просто не указывайте
`repo` для первых: они будут коммититься в корневой репозиторий.
